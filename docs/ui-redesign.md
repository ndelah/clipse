# UI redesign

The active `extension/` implements the nine UI/UX workstreams scoped in the review. Existing category routing, custom category editing, Jev/TypeSafe support, brief/detailed generation, and compatible history exports remain available.

## Implemented behavior

1. **Video context.** Saved reading and selected background jobs stay pinned across active-tab changes. Timestamp playback and regeneration use the displayed video ID. A closed source video is opened when required. Regeneration leaves the previous result readable, including after cancellation or failure; only successful completion replaces it. The back-to-History button provides an explicit exit. The panel opens directly to history without navigation tabs; the embedded Clipse logo starts summarization from the YouTube player. New results appear in history for the user to open.
2. **Setup.** First use explains captions, local history, direct OpenAI processing, API credit, and potentially multiple requests for longer videos. An illustrative sample works without credentials and has no playback, generation, or save actions. Settings provides a key-management link, a connection check, and model input under Advanced. New key/model settings are checked before saving; validation checks key/model access without generating content or guaranteeing available credit. Both settings entrypoints use shared controls. First-run setup appears within History. After saving settings, Done returns to History; the player logo starts summarization using the saved preferences.
3. **Reading.** The video title leads the reading hierarchy, followed by quiet channel/duration metadata, a regular-weight overview, and an audience-oriented recommendation. Copy and Markdown download are labeled icon buttons below the summary text. The video title uses the full card width. Caption provenance lives in About this video. Takeaways have no divider lines; only their timestamp buttons are interactive and underlined. Takeaways precede expandable full prose. Classification and transcript limitations live in About this video. Full-summary and About disclosures retain their state while a summary is being read. Separate learning outcomes are no longer rendered in the panel; old fields remain portable in exports.
4. **Evidence.** Transcript rows receive stable IDs across single and chunked requests. Intermediate notes retain IDs for final synthesis. Model-provided IDs are checked against actual extracted rows; excerpt text and playback time are taken from those rows, not generated by the model. Unknown references lose their timestamp/source. The panel offers timestamp playback without source disclosures or duplicate playback links. Linked excerpts remain available in exports. Older summaries remain readable. Matching an ID validates provenance, not whether the speaker's claim is true or whether the excerpt fully supports the interpretation.
5. **Processing/recovery.** Named stages and section counts replace estimated percentages. Guidance changes after extraction. A compact background list lets users inspect jobs for other videos; completed background summaries offer an in-panel Read action. Stop is neutral, failures keep technical diagnostics behind disclosure, and key/model/credit, captions, reload, timeout/network problems lead to different next actions. Retry explicitly restarts and can incur further API charges; there is no partial-resume claim.
6. **Library.** History titles open summaries; YouTube links open sources separately. Search covers titles, channels, overview, prose, and takeaway text. The Save feature and Saved filter are removed; completed summaries remain in local history automatically. Individual deletion offers persistent one-operation undo. Clear all sits in Manage history and requires confirmation with the full count, including records hidden by search. Copy and Markdown include source/timestamp links. Backup/restore uses the existing version-1 JSON format, preserves evidence and ignores legacy saved markers, rejects malformed public fields and unsafe source URLs, limits input to 10 MB, and reports added/updated/skipped records. Keys/settings are excluded.
7. **Languages.** Caption language defaults to Best available; choices show the active video's actual track names. The ready screen and settings can select a specific track. Direct extraction uses that track. Rendered fallback attempts selection and checks the actual panel metadata; unavailable/unverifiable choices fail explicitly rather than silently choosing another language. Summary language defaults to Same as captions for new profiles, with searchable suggestions and custom language entry. Existing explicit language preferences are retained. Source/output languages participate in configuration-aware cache checks; old results never regenerate automatically.
8. **Navigation/brand.** Video and History are the primary destinations; Settings is a labeled header action with a return route. The supplied mark appears in the panel/options page and as raster toolbar/extension icons. All runtime assets live inside the extension folder. Narrow layouts wrap controls and long titles.
9. **Accessibility.** Icon buttons expose accessible names and tooltips, native disclosures are keyboard accessible, and status/error announcements identify milestones without reading every elapsed-time tick. Explicit navigation and hidden-control transitions manage focus. Focus styling, reduced motion, readable secondary text, and both system themes cover panel and options. Deletion moves focus to Undo, then search after restoration.

## Validation and practical limits

- Node regression tests mock Chrome/DOM/provider boundaries and cover video identity, pinned reading, regeneration/cancellation, source IDs and chunk synthesis, actual/selected languages, history and queue mutations, configuration, settings, and recovery.
- Optional `npm run check:ui` uses Playwright and installed Chrome in an isolated headless profile. All HTTP requests are fulfilled from local extension files; Chrome storage/tabs/provider responses are mocked. It checks real module/DOM/CSS rendering, narrow widths (200/320/400/600 px), both themes, panel/options, and principal setup/library/processing interactions. Screenshots go to ignored `dist/ui-check/`.
- `npm run check` validates syntax, module/resource references and versions. `npm run package` creates the loadable ZIP.
- Live YouTube selector compatibility, real provider generation, native extension API integration, and a physical screen-reader pass are separate release checks. Automated browser fixtures cannot establish those outcomes. The rendered-language menu is deliberately conservative: failure to verify its selection produces a recoverable error.
- Raw transcripts and section notes are not saved. Only linked caption excerpts are stored with the summary. Restart can repeat prior paid API work. One latest summary per video is retained, with no version browser, sync, chat, quiz, playlist, or batch workflow.

## Optional developer tooling

Runtime and Node tests remain dependency-free. Rendering checks require Playwright and Chrome; icon regeneration requires sharp. Either install those tools locally or point `PLAYWRIGHT_MODULE` / `SHARP_MODULE` to their package entrypoints. Generate icons with `npm run icons:generate`; the original SVG stays unchanged.
